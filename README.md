# 景点评级 · 从夯到拉完了

我去过的景点，五档分级：**夯 → 顶级 → 人上人 → npc → 拉完了**。

👉 https://froxieye.github.io/scenic-tiers/

![预览](shot-dense.png)

> 上图是 60 条示例数据，为了看清装满的样子。仓库里只带一条真实记录（黄岩石窟 / 顶级）。

## 设计

整张表就是一块俄罗斯方块的井：每一档是井里的一行，每个景点是落进那行的方块。

- 五档各配一个真实的四格骨牌——夯=I、顶级=T、人上人=L、npc=S、拉完了=Z。形状和颜色双重编码档位，不靠颜色也分得清。
- 配色不是俄罗斯方块的标称色。那套色是 1989 年给 CRT 定的，当年经过显像管衰减出来是柔的；
  按字面值铺成现代 sRGB 大色块、再压在冷蓝黑底上，就成了灯管。这里改成「落灰的街机柜」：
  暖调炭灰底，颜料般的低饱和色，平均饱和 34%（标称色是 79%）。
- 档位色的叙事是**暖色高饱和 → 中性 → 冷色低明度**：夯最烈，npc 最中性（"什么都不是"），
  拉完了又冷又暗（"主动差"）。填充色和档位名文字色分开——填充可以暗，压在井底的字必须亮到 4.5:1。
- 像素字没有粗体（强行加粗会糊），所以层级只靠字号和颜色，字号一律取 12 的整数倍。
- 全站零圆角、零模糊阴影，只有硬偏移和内嵌斜角（斜角高光压到 18%，再高就成反光了）。
- 只有一个动效，且由操作触发：新方块分步落下，该行闪一次。`prefers-reduced-motion` 下自动关闭。

**方块为什么只有名字。** 一开始方块里塞了名字、地点、时间、一句话和两个按钮——那是卡片的信息量，不是方块的。
实测 60 个景点要 4116px、4.6 屏，一行只排得下 2 个，再多就没法扫了。
现在方块只留名字、宽度由文字决定，同样 60 个景点是 1252px、1.4 屏，一行 5 个。
详情收进弹窗，点方块就开；写了一句话的方块右上角点一个点。测试里有一条密度回归盯着这个数。

## 用法

| 做什么 | 在哪 |
| --- | --- |
| 加一个景点 | 右侧 NEXT 里的「投一个」（手机在屏幕底部） |
| 看详情 / 改 / 删 | 点方块本身，在弹窗里操作 |
| 快速瞄一眼详情 | 鼠标悬停在方块上 |
| 按名字或地方找 | 右侧「找景点」 |
| 备份 / 恢复 | 右侧「存档」的导出、导入 |

方块右上角有个小点，表示这条写了一句话。

## 数据存在哪

浏览器的 localStorage，**按设备存，不上传服务器**。手机上加的，电脑上看不到。
换设备或清缓存前记得导出 JSON。

存档格式是一个数组，字段：`id` `name` `where` `when` `tier` `said`。
`tier` 取 `hang` / `top` / `ren` / `npc` / `la`。旧版的 `place` `date` `note` 字段读进来会自动迁移。

## 本地跑

整站就是一个 `index.html` 加一个字体文件，没有依赖、不用构建。

```bash
python3 -m http.server 8000
# http://127.0.0.1:8000/
```

直接双击打开也行，但 Safari 会禁用本地文件的 localStorage，改动不会保存——
那种情况页面会给出提示，用上面的本地服务打开即可。

## 改档位

档位的名字、注解、颜色、骨牌形状都写在 `index.html` 里的 `TIERS` 数组，改那几行就行。
